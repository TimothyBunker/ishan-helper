Rationality
•As we discussed last time, “intelligence” is an ill -defined 
concept.
•Let us assume a performance measure that is given (and 
usually external) to the agent
–For example:
•$1 per room cleaned
•$10 per room cleaned minus $1 per movement
•$10 per room cleaned minus $3 per movement
•etc.
•Rational Agent :
–Chooses actions that maximize the expected value of the 
performance measure given the current percept sequence.

Properties of Environments
•(Fully) Observable: The agent can sense the entire state of the 
environment (else: Partially Observable )
•Deterministic : The outcome of actions is determined by the 
state of the board and the action executed (else: 
Nondeterministic or Stochastic )
•Sequential : Action outcomes can be affected by prior actions 
(else: Episodic ).
•Static : State of the world doesn’t change during deliberation 
between actions (else: Dynamic )
•Discrete : Actions can only be performed in a small fixed number 
of ways (else: Continuous )
•Single -Agent : There is only one agent of change
(else : Multi -Agent )

•Initial state: S0
–Initial configuration of the problem (e.g. starting position in a 
maze)
•Actions: A

•Goal condition: G

given sequence of actions is a solution to the problem or not
•Cost function: c
–A function that assigns a numeric cost to a given sequence of 
actions

Problem Types
•Deterministic, fully observable:
–Solution: [down, down, down,
right, down, …]
•Non -deterministic or partially observable:
–Agent might not know its exact coordinates, must rely 
on percepts to tell them about the walls around them
–Solution, policy (mappings from percepts, or states, to 
actions):
•If no wall on left, then turn left
•If wall on left, no wall ahead, then advance
•If wall on left, wall ahead, then turn right
–For example: the “follow the right/left wall” strategy

Review
•OPEN (or Fringe) list = nodes queued for processing
•CLOSED list = nodes/states we’ve already processed
•Breadth -first Search
–Remove the first node in the list
–Check if that first node’s state is a goal state
•If it’s a goal, you’re done
•If not, add children to end of OPEN list and repeat
•Depth -first Search
–Same as BFS, except add children to start of OPEN list.
•How can you check if a state is a repeated state?
–Check whether it’s already in either OPEN or CLOSED

A Note on Graph Search
•Repeated -state checking:
–When the search state is a graph, strategies like DFS can get 
stuck in loops
–To avoid this, we generally want to keep a list of already -
visited nodes –a "CLOSED" list
•In DFS:
–If we want to avoid repeating states completely, we need to 
keep ALL visited states in memory (in the CLOSED list)
–If we just want to avoid loops, we only need to remember 
the current branch (linear memory as a function of m= 
maximum depth)

A* Search
•Pronounced “A -Star”
•At each cycle, expand the node with the lowest f(n)
f(n) = g(n) + h(n)
•A* implementations assume repeated -state 
checking (i.e., assume the search space is a graph)
•Thus, they use two lists simultaneously:
–OPEN: list of nodes that need to be processed
–CLOSED: list of nodes that have already been processed

Systematic vs. Local Search
•All the algorithms we have seen so far have been 
“systematic”:
–They will systematically explore ALL the states in the search space 
if needed
•Each of them just explores the states in a different order
–If the search space is finite, they are all complete
•Local Search:
–Instead of systematically exploring the state space…
–Start with one state (even a bad one) and iteratively improve it by 
exploring neighbor states (“local”)
–Search space is the set of all states visited
–Iterative improvement

Iterative Improvement Algorithms
•In many optimization problems, path is irrelevant
–Goal state itself is the solution
•Then state space = set of “complete” configurations
–Find optimal configuration, e.g., TSP
–Or, find configuration satisfying constraints, e.g., timetable
•In such cases, can use iterative improvement algorithms
–keep a single “current” state and try to improve it
•Constant space, suitable for online as well as offline 
search

•Given a list of children, which one do we explore
in each iteration of MCTS? 
•Ideally, we want:

–But maybe spend a little time exploring bad children,

happen that we were just unlucky, and a child we thought was 
bad is actually good)
•Simplest idea: ε -greedy
–With probability 1 -ε: choose the current best
–With probability ε: choose one at random

Grammar
•Vervet monkeys, antelopes, etc. use isolated symbols for sentences
–Restricted set of communicable propositions, no generative capacity
(Chomsky (1957): Syntactic Structures)
•Grammar specifies the compositional structure of complex messages. 
E.g., speech (linear), text (linear), music (two -dimensional)
•A formal language is a set of strings of terminal symbols
•Each string in the language can be analyzed/generated by the grammar
•The grammar is a set of rewrite rules , e.g., 
S → NP VP Backus -Naur Form (BNF)
Article → the | a | an | …
Here S is the sentence symbol, NP and VP are nonterminals

Entropy
•Given a set of symbols S…
•Drawn from an alphabet B…
•Entropy is a measure of uncertainty of a variable
•Entropy = expected number of bits needed to 
encode the next symbol (in a sense, the amount 
of "surprise" over the outcome of the next event) 
–If Sis drawn at random from B, entropy is maximal 
–If Sis always the same symbol from B, entropy is 
minimal
•we know which symbol will come next, so there’s no new 
information

Overfitting
•What happens if we have an example in the training set 
that is noise? (e.g. that is mislabeled)
–ID3 will try to force it into the decision tree!
•This is an example of Overfitting —when what you’ve 
learned does very well on training examples,
but much less well on other examples
–In other words, it doesn’t generalize
–One of the most critical concepts in machine learning!
•For ID3, some strategies exist to avoid this
–e.g., prevent leaves that have very few examples
–e.g., stop building the tree when there would be little 
information gain in the next level

Overfitting
•More generally, what can you do?
–Use a training set and a test set
•Say, reserve 90% for training and 10% for testing
–Use cross -validation
•Repeatedly split your set into different training vs. test sets
•E.g., Leave -one-out cross -validation
–By not training on the data you’re testing, you’re 
trying to ensure generality
